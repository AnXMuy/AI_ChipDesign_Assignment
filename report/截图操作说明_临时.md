# 实验报告截图操作说明（临时交接文档）

此文档用于补齐实验报告中的真实 GTKWave 截图，不作为实验报告正文提交。报告正文已独立说明设计、验证方法和实验结果；插图后可单独提交报告。需要截取四幅波形，图号、时间范围和检查点如下。

## 1. 打开已准备好的波形

在终端执行：

```bash
cd /Users/zixuan/XJTU/AIChip
export PATH="$PWD/.conda-env/bin:$PATH"
gtkwave report/evidence/screenshot_wave.vcd conv_sim/wave.gtkw
```

默认视图已设置纳秒尺度的启动窗口。如果旧窗口仍显示满屏红色 `X`，先将顶部 `To` 改为 `160 ns` 并回车，再用菜单 `Time → Zoom → Zoom Full`（快捷键 **Ctrl+0**）。顶部 `From/To` 指定可查看的边界，时间轴上的刻度才是当前实际放大的范围。旧视图缺少缩放设置时可能只显示 0～4 ps，尚未到 5 ns 的首次复位采样沿；VCD 中各状态、地址和累加器在 5 ns 完成初始化。

四幅图还各有单独的保存视图，已选好信号、显示格式、起始位置和光标，可以分别打开：

```bash
# 图1：复位与启动。
gtkwave report/evidence/screenshot_wave.vcd conv_sim/wave_start.gtkw
# 图2：卷积核遍历与乘累加。
gtkwave report/evidence/screenshot_wave.vcd conv_sim/wave_mac.gtkw
# 图3：连续三个通道写回。
gtkwave report/evidence/screenshot_wave.vcd conv_sim/wave_write.gtkw
# 图4：最终写回与完成。
gtkwave report/evidence/screenshot_wave.vcd conv_sim/wave_done.gtkw
```

窗口宽度会影响可见的右边界，若需严格匹配下文范围，按下一节的方法输入 `From/To` 后执行 `Zoom Full`。

本机环境已配置好。波形为本次实际运行 Icarus Verilog 生成的 VCD，完整记录一次计算，没有中途关闭记录。实验参数为输入 8×8×16、32 个 3×3×16 卷积核、填充 1、步长 1、右移位数 8、16 路通道并行，输出为 8×8×32。运行结果为 `cycles=57345 outputs=2048 errors=0`，最终输出 `PASS`。报告中的完整尺寸实验另有 2,097,152 个输出；这里选用相同计算结构的小尺寸实验展示时序细节。

若使用其他位置的 conda 环境，先激活该环境，再运行上述 `gtkwave` 命令。

## 2. 统一显示设置

1. 将窗口放大到约 1400×850 或更大，确保信号名、数值和时间轴清楚可读。
2. 保存视图已经选入所需信号。左侧层次为 `tb_conv`；状态、坐标和累加器位于其中的 `dut`。
3. 右键选中信号，在 `Data Format` 中设置显示格式：`acc_q`、`ofm_acc`、`ofm_data` 用 **Signed Decimal**；`state_q`、地址、`group_q`、`kh_q`、`kw_q`、`oc_q` 用 **Decimal**；`ofm_strb` 用 **Hex**；其余单比特信号保留二进制电平。
4. 各图按下文列出的信号保留显示即可。可临时删除无关信号行，重新打开保存视图可恢复。累加器和数据总线保留数字总线形式。
5. 调整至指定时间范围：先输入 `To` 终止时间并回车，再输入 `From` 起始时间并回车，均包含 `ns` 单位；然后用菜单 `Time → Zoom → Zoom Full`（**Ctrl+0**）显示该范围。若前一幅图已经缩小了允许查看的边界，先将 `From` 恢复为 `0 ns`、`To` 恢复为 `573540 ns`，再设置新范围。也可用缩放按钮和滚动条定位。GTKWave 支持按住鼠标右键拖选一段时间进行局部放大。以截图里实际可见的时间轴范围为准。
6. 四幅图均使用**数字电平/总线视图**，截图保留 GTKWave 的信号栏与时间轴。将鼠标放到关注时刻时，左侧数值列会给出该处总线值。

状态编码：`0=IDLE`，`1=REQUEST`，`2=WAIT_DATA`，`3=CALCULATE`，`4=WRITE_OUT`，`5=DONE`。时钟周期为 10 ns，首次上升沿在 5 ns。仿真最初 0～5 ns 的内部寄存器尚未完成首次复位赋值，显示红色 `X`；5 ns 后这些信号已确定，40 ns 解除复位，65 ns 接受启动。

## 3. 四幅必需截图

### 图 1：复位、启动与同步读取

- **建议时间范围：0～160 ns。**
- 信号从上到下：`clk`、`rst`、`start`、`state_q`、`ifm_vld`、`knl_vld`、`ifm_addr`、`knl_addr`、`acc_q`、`ofm_vld`、`done`。
- 检查点：40 ns 解除复位；`start` 在 60～70 ns 为高；65 ns 上升沿接受启动后进入状态 1；75 ns 进入状态 2；85 ns 进入状态 3；95 ns 返回状态 1。读请求有效时两个有效信号同时为高。
- 将光标放在 **70 ns** 附近，可读到首次读地址 `ifm_addr=17`、`knl_addr=29`。
- 建议保存名：`图1_复位启动与同步读取.png`。

这幅图用于说明启动后的读请求、存储器响应和锁存顺序。

### 图 2：卷积核遍历与通道乘累加

- **建议时间范围：80～350 ns。**
- 信号从上到下：`clk`、`state_q`、`kh_q`、`kw_q`、`group_q`、`ifm_addr`、`knl_addr`、`acc_q`、`ofm_vld`、`ofm_acc`、`ofm_data`。
- 检查点：`kh_q`、`kw_q` 依次遍历 3×3 核；16 路一次覆盖全部 16 个输入通道，因此 `group_q=0`。每个核位置经过请求、等待、计算三个周期。
- 累加器在前几个核位置可保持零，这是填充区输入为零的结果。215、245、305、335 ns 更新后的 `acc_q` 分别为 **−19436、−30901、−37201、−47835**。
- 将光标放在 **340 ns**，可读到最终 `ofm_acc=−47835`、`ofm_data=−128`，且 `ofm_vld=1`。
- 建议保存名：`图2_卷积遍历与乘累加.png`。

这幅图用于说明累加值如何随核位置推进，以及首次输出的饱和量化。

### 图 3：连续输出、通道选通与结果写回

- **建议时间范围：280～950 ns。**
- 信号从上到下：`clk`、`state_q`、`oc_q`、`ofm_vld`、`ofm_addr`、`ofm_strb`、`ofm_acc`、`ofm_data`。
- 检查点：前三个输出有效窗口为 **335～345 ns、615～625 ns、895～905 ns**；testbench 在对应窗口结束的上升沿 **345、625、905 ns** 采样写回。
- 在 **340、620、900 ns** 分别放置光标，检查下表。图中应同时看见三个有效脉冲和数据总线值；可增大窗口宽度，让窄总线窗口内的数字可读。

| 光标时间/ns | 输出通道 `oc_q` | 地址 | `ofm_strb`（十六进制） | 原始累加值 | int8 输出 |
|---:|---:|---:|---:|---:|---:|
| 340 | 0 | 43 | 00000001 | −47835 | −128 |
| 620 | 1 | 43 | 00000002 | 345 | 1 |

### 图 4：最后一次写回与完成脉冲

- **建议时间范围：573440～573540 ns。**
- 信号从上到下：`clk`、`state_q`、`oc_q`、`ofm_vld`、`ofm_addr`、`ofm_strb`、`ofm_acc`、`ofm_data`、`done`。
- 将光标放在 **573500 ns**，最后一个有效输出为：地址 **106**、通道 **31**、选通 **80000000**、累加值 **34284**、输出 **127**。
- 最后输出有效窗口为 **573495～573505 ns**，testbench 在 **573505 ns** 上升沿采样；随后 `done` 在 **573505～573515 ns** 为高，并在 **573515 ns** 被 testbench 采样；状态于 573515 ns 回到 0。
- 从启动接受沿 65 ns 至完成采样沿 573515 ns，共 `(573515−65)/10=57345` 个周期。
- 建议保存名：`图4_最终写回与完成脉冲.png`。

这幅图用于说明完成脉冲出现在全部输出写回后，并核对实测周期。

## 5. 需要重新生成 VCD 时

本机已准备好 `report/evidence/screenshot_wave.vcd`，可以直接截图。以下命令用于重建同一配置的全程波形；若数据已存在，可从 `mkdir` 开始执行。

```bash
cd /Users/zixuan/XJTU/AIChip
export PATH="$PWD/.conda-env/bin:$PATH"

# 生成固定种子的小尺寸输入与参考值。
python conv_sim/python/experiment.py --case small --lanes 16 --seed 20261017

mkdir -p results/screenshots
iverilog -g2012 -s tb_conv \
  -Ptb_conv.RUNS=1 -Ptb_conv.LANES=16 \
  -o results/screenshots/lanes16.vvp \
  conv_sim/rtl/conv.sv conv_sim/tb/tb_conv.sv

vvp results/screenshots/lanes16.vvp \
  +IFM=results/small/data/ifm.hex \
  +KERNEL=results/small/data/kernel.hex \
  +GOLDEN=results/small/data/golden.hex \
  +GOLDEN_ACC=results/small/data/golden_acc.hex \
  +OUTPUT=results/screenshots/output.hex \
  +METRICS=results/screenshots/metrics.json \
  +VCD=results/screenshots/wave.vcd \
  +TRACE_CYCLES=60000

gtkwave results/screenshots/wave.vcd conv_sim/wave.gtkw
```

终端应显示：

```text
run=1 cycles=57345 outputs=2048 errors=0
PASS
```

此命令生成的波形与前述四幅图使用相同时间窗口。`TRACE_CYCLES=60000` 大于单次计算周期数，因此会记录完整时序。
