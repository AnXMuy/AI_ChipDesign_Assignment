# 可配置 8-bit 卷积算子的设计、仿真与并行性能验证

课程：人工智能芯片导论

实验日期：2026 年 10 月 17 日

实现语言：Python、SystemVerilog

## 摘要

本实验围绕有符号 8-bit 卷积计算，设计了具有可配置输入通道并行度的可综合硬件，并建立整数参考计算、同步存储器仿真、逐输出自校验与波形分析相结合的验证方法。硬件采用 16-bit 乘积、32-bit 累加、算术右移和 int8 饱和量化。完整尺寸实验以 256×256×16 输入和 32×3×3×16 权重计算 256×256×32 输出，全部 2,097,152 个 int8 输出及对应 int32 原始累加均与参考一致，实测耗时 58,720,257 个周期。为检验参数变化与数值边界，进一步设计 8 类配置、17 组参数实验，每组完成两次任务，全部错误数为零。同一计算任务在 1、4、16 路并行度下分别需要 333,825、112,641、57,345 个周期，16 路相对串行取得 5.821 倍周期加速。综合检查确认相应数据乘法器数量确为 1、4、16，验证了性能变化与硬件并行资源之间的对应关系。

## 1. 实验目的与总体设计

本实验的首要目的是将卷积的数学定义转化为位宽明确、时序清楚、能够独立验证的硬件实现。为此，需要统一 Python 与 RTL 对有符号数、数据布局、填充、步长和量化的理解；仅比较最终图像或少量输出不足以判断这些环节是否正确，因此本实验对每个输出同时比较量化前累加值和量化后 int8 值，并检查写回地址与通道使能。

第二个目的是检验硬件对不同卷积参数的适应能力。为此，我们选择矩形输入、非方形卷积核、不同填充与步长、不能整除并行度的输入通道数，以及定向量化边界作为实验条件。每组任务还重复执行，以检验复位和重新启动后的状态初始化。

第三个目的是解释输入通道并行化的收益与代价。我们保持数据、输出数量和控制协议一致，仅改变每拍处理的输入通道数，用实测周期评价加速，并通过综合后的乘法器数量判断并行参数是否形成实际硬件资源。实验采用同步读存储器模型，每个核位置的读取与计算时序独立可观察，因此可以建立可逐拍核对的周期模型。

完整尺寸实验采用输入高、宽均为 256，输入通道数为 16，输出通道数为 32，卷积核为 3×3，四边填充 1，步长 1。该配置能够同时验证大规模地址遍历、全部输出通道写回和定点计算的持续正确性。

## 3. 卷积定义与定点数据表示

### 3.1 输出尺寸与卷积运算

设输入为 $X\in\mathbb{Z}^{H\times W\times C_{in}}$，权重为 $K\in\mathbb{Z}^{C_{out}\times K_h\times K_w\times C_{in}}$，四边填充宽度为 $P$，步长为 $S$。输出尺寸为

$$
H_o=\left\lfloor\frac{H+2P-K_h}{S}\right\rfloor+1,\qquad
W_o=\left\lfloor\frac{W+2P-K_w}{S}\right\rfloor+1.
$$

采用神经网络中常见的互相关定义，输出位置 $(y,x)$、输出通道 $n$ 的累加为

$$
A_{y,x,n}=\sum_{i=0}^{K_h-1}\sum_{j=0}^{K_w-1}\sum_{c=0}^{C_{in}-1}
X_{pad}[yS+i,xS+j,c]K[n,i,j,c].
$$

本层偏置为零，激活采用恒等映射，便于直接检验卷积与量化逻辑。输入和权重均在 $[-128,127]$ 范围内。单个乘积采用有符号 16 位表示；组内和及跨核位置累加均采用有符号 32 位表示。

主实验每个输出包含 $3\times3\times16=144$ 个乘积。以单个乘积绝对值不超过 16,384 估计，最坏累加绝对值上界为 2,359,296，处于 int32 范围内。参考计算使用 int64，并在导出前检查累加范围，以避免参考实现自身的位宽溢出。

### 3.2 量化规则

累加完成后，先执行算术右移，再饱和到 int8：

$$
Y_{y,x,n}=\operatorname{clip}\left(A_{y,x,n}\mathbin{\ggg}Q,-128,127\right),
$$

其中 $Q$ 为可配置移位量，主实验取 8。算术右移保持符号，负数按向负无穷取整的规则处理，例如 $-3\ggg1=-2$。这一规则决定了负奇数的结果，不能用向零截断代替。

最终 int8 值与原始 int32 累加均作为参考输出。采用双层比较的理由是：不同的错误累加可能同时被饱和为 127 或 −128，单独比较饱和后的值会掩盖这类内部运算错误。

## 4. 具体实现与验证机制

### 4.1 数据生成、补零与通道打包

为获得可重复的串并行对照，我们使用固定种子生成覆盖完整 int8 范围的输入和权重，同一配置的不同并行度复用完全相同的数据。Python 先在空间边界补零，硬件随后只需要读取合法的补零后地址。完整尺寸的补零输入为 258×258×16。

每个存储字保存一个空间位置的全部输入通道，通道 0 放在最低 8 位。权重按“输出通道、核行、核列、输入通道”的顺序排列，同一核位置的输入通道也打包为一个字。这样一次输入和权重读取就可供后续若干通道组复用，主实验读总线宽度均为 128 位。

打包时使用掩码保存负数的补码，再按通道逆序输出十六进制字段：

```python
mask = (1 << bits) - 1
for row in values:
    packed_word = "".join(
        f"{int(value) & mask:0{bits // 4}x}"
        for value in row[::-1]
    )
    stream.write(packed_word + "\n")
```

逆序输出使十六进制文本最右侧对应通道 0，与 RTL 的低位切片一致。相同布局同时用于输入、权重、8-bit 参考、32-bit 累加参考及打包输出，避免在数据传递过程中重复变换通道顺序。

### 4.2 Python 整数参考

为了在保持整数精度的同时完成完整尺寸参考计算，我们逐个核位置提取带步长的输入窗口，再使用通道收缩完成乘积求和：

```python
acc = np.zeros((OH, OW, COUT), dtype=np.int64)
for kh in range(KERNEL_H):
    for kw in range(KERNEL_W):
        window = padded[
            kh:kh + OH * STRIDE:STRIDE,
            kw:kw + OW * STRIDE:STRIDE,
            :,
        ]
        acc += np.einsum(
            "hwc,nc->hwn",
            window.astype(np.int64),
            kernel[:COUT, kh, kw].astype(np.int64),
            optimize=False,
        )
assert np.max(np.abs(acc)) < 2**31
quantized = np.clip(acc >> SHIFT, -128, 127).astype(np.int8)
```

该实现将输出空间坐标与核坐标显式分离，能够直接表达不同核高宽和步长。为独立验证预补零和窗口切片，我们在小尺寸参数实验中另用标量循环计算原图坐标。其核心为：

```python
iy = oy * STRIDE + kh - PAD
iw = ox * STRIDE + kw - PAD
if 0 <= iy < H and 0 <= iw < W:
    value += int(image[iy, iw, ci]) * int(kernel[co, kh, kw, ci])
```

两种 Python 实现分别从补零张量和原图边界出发，结果逐项相等后再作为硬件参考。这样能够降低相同寻址错误同时进入参考端与硬件端的可能性。

### 4.3 同步读协议与地址发生器

为了使访存时序能够被明确验证，硬件采用“请求、锁存、分组计算、写回”的组织方式。状态定义如下。

| 状态 | 编码 | 动作及设置理由 |
|---|---:|---|
| IDLE | 0 | 接收启动、锁存基址、初始化坐标和累加器 |
| REQUEST | 1 | 同时发出输入和权重读请求，保证两个操作数属于同一核位置 |
| WAIT_DATA | 2 | 锁存同步存储器返回的数据，使后续计算使用稳定操作数 |
| CALCULATE | 3 | 完成当前通道组的乘累加并推进核坐标 |
| WRITE_OUT | 4 | 写回一个输出通道后清零累加器，推进输出坐标 |
| DONE | 5 | 最后一次写回后产生完成电平，下一拍返回空闲 |

地址生成直接使用输出坐标、核坐标和任务基址：

```systemverilog
ifm_addr_o = ifm_base_q
    + (oh_q*STRIDE + kh_q)*PADDED_W + ow_q*STRIDE + kw_q;
knl_addr_o = knl_base_q
    + (oc_q*KERNEL_H + kh_q)*KERNEL_W + kw_q;
ofm_addr_o = ofm_base_q + oh_q*OW + ow_q;
```

输入行跨度采用补零后的宽度，输出行跨度采用输出宽度，因此输入和输出高宽可以独立变化。接口为 20 位地址；验证中输入、权重和输出基址分别取 17、29、43，使每次访问都包含非零地址偏移，检查是否存在忽略基址的实现错误。

测试平台在请求有效的上升沿用非阻塞赋值更新读数据，RTL 在下一上升沿锁存：

```systemverilog
// 测试平台中的同步读存储器。
if (ifm_vld)
    ifm_data <= ifm_mem[ifm_addr-IFM_BASE];

// 硬件状态机中的接收过程。
REQUEST: state_q <= WAIT_DATA;
WAIT_DATA: begin
    ifm_q <= ifm_data_i;
    knl_q <= knl_data_i;
    state_q <= CALCULATE;
end
```

由于两个时钟过程均在上升沿触发，非阻塞赋值使请求沿后的数据在该沿结束时更新，下一沿才能可靠锁存。将请求和锁存分开，使这一时序关系直接反映在状态机和波形中。

复位采用异步高有效，清零全部状态、坐标、基址、操作数寄存器及累加器。启动在空闲态被采样，运行过程中保持本次任务已锁存的配置，任务结束后可再次启动。

### 4.4 可配置通道并行计算

为在同一实现中比较串行和并行方案，设每拍处理的输入通道数为 $L=\texttt{LANES}$，每个核位置需要

$$
G=\left\lceil C_{in}/L\right\rceil
$$

组计算。硬件通过生成结构实例化 $L$ 个有符号 8×8 乘法器，用组计数器选择当前通道。对于最后一组不足的通道，输入和权重置零：

```systemverilog
wire signed [7:0] x = (group_q*LANES + lane < CIN)
    ? $signed(ifm_q[(group_q*LANES + lane)*8 +: 8]) : 8'sd0;
wire signed [7:0] w = (group_q*LANES + lane < CIN)
    ? $signed(knl_q[(group_q*LANES + lane)*8 +: 8]) : 8'sd0;
assign product[lane] = x*w;
```

这种屏蔽方式允许输入通道数为 5、7 等不能整除并行度的数值，也允许并行度大于输入通道数。每个乘积为有符号 16 位，在组内求和前显式符号扩展：

```systemverilog
group_sum = 32'sd0;
for (integer n = 0; n < LANES; n = n + 1)
    group_sum = group_sum + {{16{product[n][15]}}, product[n]};

// 当前组求和后，在时钟沿更新整个输出的累加。
acc_q <= acc_q + group_sum;
```

显式扩展保证负乘积进入 32 位加法后仍保持原值。核列、核行及通道组依次完成后，状态机进入写回态；写回后将累加器归零，继续计算下一个输出通道。1 路与 16 路版本共享相同的寻址和输出协议，因此性能对照只改变计算并行度。

### 4.5 量化、独热写回与双层检查

量化逻辑首先执行有符号右移，再以有符号上下界判断饱和：

```systemverilog
shifted = acc_q >>> SHIFT;
if (shifted > 32'sd127) ofm_data_o = 8'h7f;
else if (shifted < -32'sd128) ofm_data_o = 8'h80;
else ofm_data_o = shifted[7:0];
```

每次有效写回只包含一个 8-bit 输出。输出地址表示空间位置，通道独热码表示该字内需要更新的通道；通道 0 对应最低位使能。测试平台据此将逐通道结果收集为完整输出张量。

参考数据通过十六进制存储字装载。每个写回沿先检查地址范围和独热码，再比较原始累加与量化值：

```systemverilog
$readmemh(ifm_path, ifm_mem);
$readmemh(kernel_path, knl_mem);
$readmemh(golden_path, golden);
$readmemh(golden_acc_path, golden_acc);

if (ofm_data !== golden[position][channel*8 +: 8])
    errors = errors + 1;
if (ofm_acc !== golden_acc[position][channel*32 +: 32])
    errors = errors + 1;
```

比较采用四态不等运算符，确保未知值不能被误认为正确结果。控制信号和输出总线另用归约异或检查 X/Z：

```systemverilog
if ((^{ofm_addr, ofm_strb, ofm_data, ofm_acc}) === 1'bx)
    $fatal(1, "unknown output");
```

平台为每个输出通道设置已写回标记，检查重复、缺失和遍历次序，完成时要求输出数量等于 $H_oW_oC_{out}$，并设置周期上限与独立仿真超时。最终输出还由 Python 解包后再次比较 int8 参考。任何数据或协议错误均使测试以非零退出码结束，因此自动运行结果具有明确的通过与失败判据。

### 4.6 周期模型与测量口径

设输出标量数为 $N=H_oW_oC_{out}$。每个核位置包含一拍读请求、一拍数据锁存和 $G$ 拍分组累加，每个输出包含一拍写回，因此启动采样沿至完成采样沿的周期差为

$$
T=N\left[K_hK_w(G+2)+1\right]+1.
$$

最后的 1 对应完成采样相对最后写回的延后。测试平台在每次任务中实测周期并逐次检查上述公式。加速比采用相同任务的串行周期除以并行周期；10 ns 时钟下的模拟时间由周期乘以 10 ns 得到。主机墙钟时间另行计时，用于记录仿真执行成本。

## 5. 真实波形的时序验证

为了验证控制和数据采样关系，我们选择 8×8×16 输入、32 个输出通道、3×3 卷积核、16 路并行的配置，记录真实仿真信号。该配置与完整尺寸采用相同的通道数和单输出计算步骤，适合在较短时间窗口内观察启动、连续写回和任务结束。

### 6.3 相同任务下的串并行性能

为隔离并行度对性能的影响，我们固定输入 8×8×16、输出通道 32、3×3 核及同一随机数据，只改变 LANES。判据包括所有输出一致、周期符合理论模型，以及并行配置较串行减少周期。

| LANES | 每核位置组数 G | 单输出周期 | 实测总周期 | 模拟时间/ms | 周期加速比 | 两次任务墙钟/s |
|---:|---:|---:|---:|---:|---:|---:|
| 1 | 16 | 163 | 333,825 | 3.33825 | 1.000 | 4.484 |
| 4 | 4 | 55 | 112,641 | 1.12641 | 2.964 | 3.486 |
| 16 | 1 | 28 | 57,345 | 0.57345 | 5.821 | 1.051 |

三种实现的输出完全一致。16 路的周期减少至串行的约 17.18%，但加速未达到 16 倍，原因可由周期构成直接解释：串行单输出需要 $9(16+2)+1=163$ 拍，16 路需要 $9(1+2)+1=28$ 拍。通道计算拍数减少后，请求、锁存和写回占据更大比例，因此总加速约为 $163/28$，与实测 5.821 倍一致。

矩形配置的输入通道数为 5，8 路已经可以一组完成，实测加速为 2.286 倍；单通道定向配置在 1 路与 4 路下都只有一组，周期均为 33。两项结果进一步表明，性能取决于实际通道分组数，而并行路数增加到覆盖全部输入通道后，组数不会继续下降。

完整尺寸完成了 16 路全量实测，串并行对照采用上述固定的小尺寸任务。两项实验使用同一硬件结构、存储协议与周期定义。墙钟时间同时受仿真事件数量和检查开销影响，硬件加速结论以周期比为依据。

### 6.4 综合结构与资源代价

为确认并行参数改变了实际硬件，我们将 1、4、16 路配置分别展开，进行过程转换、优化、结构检查和单元统计。判据为结构检查报告零问题，并且输入宽度均为 8 位、输出为 16 位的有符号数据乘法器数量等于 LANES。

| LANES | 有符号 8×8 数据乘法器 | 全部乘法单元 | 加法单元 | 触发器位数 | 通用单元总数 | 结构检查问题数 |
|---:|---:|---:|---:|---:|---:|---:|
| 1 | 1 | 4 | 16 | 543 | 103 | 0 |
| 4 | 4 | 7 | 22 | 543 | 127 | 0 |
| 16 | 16 | 19 | 46 | 543 | 223 | 0 |

综合后的数据乘法器严格对应 1、4、16 路。全部乘法单元中另外包含 3 个地址运算单元，因此采用运算宽度及有符号属性区分数据通路，能够避免高估并行 MAC 数量。

从 1 路增加到 16 路，通用单元数由 103 增至 223，增加主要来自乘法、组内求和与通道选择；触发器仍为 543 位，表明控制状态和操作数寄存器规模保持一致。结合周期结果，16 路在通用单元约增至 2.165 倍时取得 5.821 倍周期加速，体现了本结构中增加通道计算资源的收益。这里的单元统计对应通用 RTL 综合阶段；目标器件的 LUT、DSP、面积和最高频率需要在具体器件映射与时序分析中确定。

| 1 | 8 | 513 | 2 | 0 |

全部结果与参考一致，说明在新启动时坐标、累加器和任务配置能够正确初始化，并且输出循环按实际输出通道数结束。

为验证自校验平台确实能够发现错误，我们进一步将第一个 int8 参考输出翻转 1 位，保留输入、权重和硬件计算不变。正常结果为 −19，损坏后的参考为 −20。测试平台在两次任务中均报告不匹配，累计错误数为 2，并以退出码 1 结束。故障注入的预期判据是“必须失败且报告数据不匹配”，实测满足该判据，证明从参考装载、逐值比较到错误退出的检测链路有效。

## 7. 实验总结与心得

硬件的高、宽、输入通道、核高宽、权重存储通道数、实际输出通道数、填充、步长、移位和并行度均可在编译时配置，三个存储基址与启动信号在运行时配置。通道数不要求整除并行度，核高宽也不要求相等。合法配置需满足输入、核、步长和并行度为正，填充非负，输出尺寸为正，实际输出通道数不大于权重存储通道数；各存储访问范围需处于 20 位地址空间内，移位量取 0～31，数学累加需处于 int32 范围内。

本实验验证了上述 17 组离散参数组合、独立重启配置以及完整尺寸主实验。结果说明所测配置下的地址、尾组与量化边界均按设计工作。参数化表达提供了扩展其他合法组合的基础，新配置仍应遵循相同的参考比较、周期和协议判据。

通过本实验，我们认识到数据表示与采样时序是软件参考和硬件实现一致的基础。通道 0 位于低位的统一约定，将文件打包、乘法输入切片和输出收集连接起来；显式有符号扩展与 int32 累加，使定点规则直接体现在数据通路中；请求和锁存分离，则将同步存储器延迟变为可逐拍验证的状态序列。

完整尺寸的全部 2,097,152 个输出及原始累加逐项一致，参数实验和故障注入分别验证了配置边界与检测机制，周期模型又与每次任务的实测计数一致。在性能方面，通道并行化减少了归约轮数，但访存控制仍形成固定开销。后续可以在维持现有位精确判据的基础上，研究平衡加法树、计算流水化、访存与计算重叠，以及行缓存和权重复用，进一步改善频率、延迟与访存效率。
